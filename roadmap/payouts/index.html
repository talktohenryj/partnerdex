Payouts: what landed, and what is coming

A Mantle-style payout view in PartnerDex. It shows the past payouts, the payout that is open now, and the two after it. A small card on the Overview shows the same three numbers.

1 · Data check2 · Decisions3 · PlanMockup · OverviewMockup · Payouts page

Short answer. PartnerDex has almost all of the data. It holds every paid transaction (gross, net, Shopify fee, shop, date) and every live subscription with its price and last charge date. That gives exact past payouts and a good subscription forecast.

The Partner API has no payout object, so PartnerDex computes the payout calendar itself. The open question is usage that is billed but not yet paid. iziGift does not send it to Mantle, so Mantle reads it from Shopify. Sprint 0 finds out if PartnerDex can read it the same way. If not, PartnerDex estimates it from each store's past usage.

Where Mantle gets "billed" amounts

iziGift sends Mantle only the store ID, domain, email, contacts and custom fields (APIService::updateMantleProfile and the identify calls). It sends no usage amounts and no store access token. So Mantle gets its billed figures from Shopify's Partner data, not from iziGift.

There are two possible places in the Partner API:

  • The transactions feed PartnerDex already syncs. If Shopify records a usage sale when the charge goes onto the merchant's bill, PartnerDex already holds the billed usage. Only the "paid or not yet paid" flag is missing.
  • The new historical events query (unstable API version). It lists charges and earnings, and each earning has a settlementDate. An earning with no settlement date yet is a billed, unpaid amount.

What Mantle Brain says (Mantle's own open rebuild guides, Hey-Mantle/mantle-brain). Mantle pulls Shopify's transactions from the Partner API into a charges table on a schedule. Each charge has a status: upcoming, billed, due or paid. Payout = net − refunds − taxes − app credits, bucketed into 1st–15th and 16th–month end windows. App credits cut the payout but never MRR. So Mantle's "billed" amounts come from the same transactions feed PartnerDex already syncs.

One detail matters for the calendar. Mantle's customer list shows two dates per store: the app billing date (Root Rescue: Sep 28) and a later Shopify bill date (Oct 1x). Mantle puts Root Rescue's $3.99 in the Oct 1–15 payout, not Sep 16–30. So the payout window follows the date the merchant pays their Shopify bill, not the date the app charge was created. Sprint 0 confirms this with real transactions.

Sprint 0 tests both. The test is quick: compare PartnerDex's Oct 1–15 transactions with Mantle's customer list for the same period (for example, New West KnifeWorks $108.24).

3 · Plan

"Engine" is the back end: the calculations, the API, and the tests. It changes nothing on the screen. "Screens" is the front end: the Payouts page and the Overview card that read from the engine. No schema change in either.

Sprint 0 · half a day

Find the billed data

  • Compare PartnerDex transactions for Oct 1–15 with Mantle's list for the same period.
  • Run the unstable historical events query (charges, earnings, settlementDate) with the PartnerDex token.
  • Result: "billed" is exact (from Shopify) or estimated (from past usage). This choice sets the forecast in sprint 1.
  • Henry approves the mockups in the same step.
Sprint 1 · engine (back end)

Payout calendar, history, forecast

  • src/payouts/calendar.ts: 1st–15th and 16th–end periods, payout date 5 business days after the period ends.
  • src/payouts/history.ts: net, gross and fee per period, split into subscription, usage, one-time and adjustments.
  • src/payouts/forecast.ts: subscriptions due + usage (billed if sprint 0 finds it, else the per-store estimate with a range).
  • Backtest: run the forecast "as of" day 4 of each past period and compare it with what landed.
  • GET /api/payouts and a partnerdex payouts CLI command. README section.
  • Tests: month ends, weekends, February, churn and frozen stores, backtest.
Sprint 2 · screens (front end)

Payouts page and Overview card

  • The approved Payouts page under Reports: period stepper, four tiles, daily chart, per-store table.
  • The approved Payouts card on the Overview.
  • Henry sees both screens with his real numbers on a preview before merge.
  • Upstream pull request with documentation and screenshots.
