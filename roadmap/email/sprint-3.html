Sprint 3 — Delivery + history

Not started · repo: partnerdex · branch email/s3-delivery off email-upstream · no migration (columns shipped in 5)

Why this ships now

After S2, PartnerDex knows what it handed to Resend, not what happened next. A hard bounce or a spam complaint is recorded only inside Resend, so the Contacts page still shows that person as sendable, and the next audience still counts them. Henry also cannot answer "did anyone click?" or "what did we last send this merchant?". This sprint brings Resend's delivery events back into email_sends and the suppression store, and shows them per campaign and per person.

Why this is independently deployable

A new public webhook route and new reads. Nothing in S2's send path changes. With RESEND_WEBHOOK_SECRET unset the route answers 503 and the campaign page shows sent counts only — exactly S2. Writes into existing state are limited to suppressContact() with the already-allowed 'resend_webhook' source.

Build

  1. Config — src/config.ts email.resendWebhookSecret from RESEND_WEBHOOK_SECRET (the whsec_… value Resend shows when you add the endpoint). Add to .env.example and resetEnvironment().
  2. Signature check — src/email/webhook.ts (new) verifyResendSignature(rawBody: Buffer, headers, secret): boolean. Resend signs with Svix: key = base64-decode of the secret after whsec_; signed content = svix-id + "." + svix-timestamp + "." + rawBody; HMAC-SHA256, base64; svix-signature holds space-separated v1,<sig> entries — accept if any matches (timingSafeEqual). Reject when |now − svix-timestamp| > 300 s. No dependency.
  3. Event handler — src/email/webhook.ts applyResendEvent(event, db) Look up email_sends by resend_id = event.data.email_id. Not found → ignore (test sends, or other senders on the same Resend account). Stamps use COALESCE(col, @at) so the first event wins and redelivery is harmless.
    Resend typeWrite
    email.delivereddelivered_at
    email.bouncedbounced_at; if data.bounce.type is Permanent (hard): suppressContact(email, { source: 'resend_webhook', reason: 'hard bounce' }). Transient/undetermined: stamp only.
    email.complainedcomplained_at + suppressContact(…, { source: 'resend_webhook', reason: 'spam complaint' })
    email.openedopened_at (first)
    email.clickedclicked_at (first)
    anything else (email.sent, email.delivery_delayed, …)ignored, 200
  4. Webhook route — src/server/index.ts The global app.use(express.json({ limit: '64kb' })) consumes the body, and the signature needs the raw bytes. Register app.post('/api/email/webhooks/resend', express.raw({ type: 'application/json', limit: '256kb' }), resendWebhookHandler) before that express.json line and before requireAuth. Handler: 503 if no secret; 401 if the signature fails; parse JSON; applyResendEvent; 200. Errors after a valid signature still return 200 and log (Resend retries non-2xx, and a poison event must not retry forever). Add the endpoint in Resend → Webhooks with the five event types above.
  5. Campaign report — src/email/campaigns.ts + routes getCampaign(id) gains stats: { sent, delivered, opened, clicked, bounced, complained, unsubscribed, failed, skipped } (counts of non-null columns / statuses) and rates over delivered (open, click, unsubscribe) and over sent (bounce). New: GET /api/email/campaigns/:id/recipients?filter=all|delivered|opened|clicked|bounced|complained|unsubscribed|failed|skipped&q=&limit=50&offset=0 → rows with name, email, store, status, and the event times. POST /api/email/campaigns/:id/retry-failed → failed rows back to queued (new batch keys), campaign back to sending; only for sent|failed campaigns, and only after a type-the-count confirm in the UI.
  6. Per-person history — src/email/history.ts + route emailHistory(email, db) → [{ campaignId, name, subject, sentAt, status, deliveredAt, openedAt, clickedAt, bouncedAt, complainedAt, unsubscribedAt }], newest first, joined from email_sends → email_campaigns. Route on emailRouter(): GET /api/email/contacts/:email/history (kept on the email router so the contacts router stays as it is upstream).
  7. UI
    • Campaign page (EmailCampaigns.tsx): stat tiles (Sent, Delivered, Opened ≈, Clicked, Bounced, Unsubscribed), "Opens are approximate" note, filter chips over the recipients table, "Retry N failed".
    • Contacts page (web/src/components/Contacts.tsx): new "Last email" column (campaign name + a small status) from a batched read: add lastEmailFor(emails[]) beside emailHistory() and serve it from GET /api/email/contacts/last?emails=… for the visible page only. Clicking it opens a popover with the full history.
    • Customer page Contacts tab (web/src/components/CustomerContacts.tsx): same "Last email" column.
    • Suppression source labels: resend_webhook shows the reason ("hard bounce" / "spam complaint").
  8. Tests — test/emailWebhook.test.ts, extend test/emailSend.test.ts (cases below). Sign fixture payloads with a test secret in the test itself.

  • webhook disabled without secret · rejects bad signature · rejects old timestamp · accepts any matching v1 signature
  • delivered stamps once · hard bounce suppresses · soft bounce does not suppress · complaint suppresses · unknown email id ignored · handler error still returns 200
  • campaign stats and rates · recipients filter by event · retry failed requeues only failed rows · history newest first · last email for a page of contacts

Explicitly NOT in this sprint

  • Per-link click breakdown, heatmaps, A/B tests.
  • Pulling events by polling the Resend API (webhook only).
  • Lifecycle / automation — S4.
  • Unsuppressing a bounced address automatically — a human does it on the Contacts page.
