Sprint 1 — Audiences

Not started · repo: partnerdex · branch off email-upstream · migration 4 (see Q1)

Why this ships now

The split is the hard, valuable half. Today the only filters on people are hygiene filters (ContactLinkedFilter in src/contacts/list.ts), and the store status that decides who should hear what lives privately inside src/customers/index.ts (statusOf()). This sprint joins the two: pick an app, the store statuses, and the roles, and see exactly who that is — with suppression, unlinked, and ambiguous people already removed and each person counted once.

Why this is independently deployable

One migration that only creates a table, one router behind requireAuth, one page. The only edit to existing code is extracting the per-shop status query in src/customers/index.ts into an exported helper that the Customers list keeps using unchanged, and exporting sortShops from src/contacts/list.ts. If S2 never ships, Henry still gets a counted, deduped, suppression-clean list he can export as CSV and paste into any sender.

  5. Audience model + resolver — src/email/audience.ts (new) 
    export const STATUSES = ['paying','trialing','installed','churned','gone'] as const;
export interface AudienceDefinition { appId: string; statuses: CustomerStatus[]; roles: ContactRole[] }
export interface Recipient { email: string; firstName: string|null; lastName: string|null;
  shopId: string; shopName: string|null; shopDomain: string|null; role: ContactRole; status: CustomerStatus }
export interface AudienceResult { recipients: Recipient[];
  excluded: { suppressed: number; ambiguous: number; noStatus: number; merged: number };
  byStatus: Record<CustomerStatus, number>; byRole: Record<ContactRole, number> }
export function validateDefinition(input: unknown, db?: Db): AudienceDefinition   // throws EmailError(…, 422)
export function resolveAudience(def: AudienceDefinition, db = getDb()): AudienceResult
    validateDefinition: appId normalized with normalizeAppId() and checked with assertAppInScope(); statuses and roles non-empty subsets of the allowed values, deduped. EmailError mirrors ContactsError (message + status) in src/email/errors.ts.
    resolveAudience, in this order:
    1. Load candidate memberships: SELECT cs.email, cs.shop_id, cs.role, cs.match_method, c.first_name, c.last_name, c.is_suppressed, (sup.email IS NOT NULL) AS hard_suppressed FROM contact_shops cs JOIN contacts c ON c.email = cs.email LEFT JOIN contact_suppressions sup ON sup.email = cs.email WHERE cs.app_id = @appId AND cs.role IN (…roles). Unlinked people have no row here, so they are out by construction.
    2. Join each row to shopStatuses(db, appId). No entry → count in noStatus, drop. Status not in statuses → drop silently (not "excluded", just not asked for).
    3. match_method = 'ambiguous' → count in ambiguous, drop (Q3).
    4. is_suppressed = 1 or a contact_suppressions row → count in suppressed, drop. Both checks, because the mirror can lag a hand-edited row.
    5. Group survivors by email; keep the first by sortShops order (owner, then MRR); each extra row adds 1 to merged.
    6. Sort recipients by shop name, then email. Fill byStatus / byRole from the kept rows.
    Counting suppressed/ambiguous/noStatus is per person (distinct email) among those who matched the status + role filter, so the UI line "12 left out" is a number of people.

Tests (named)

  • resolves paying owners for one app · role filter excludes staff without counting them · dedupes a multi-store person to the owned store
  • excludes suppressed via mirror · excludes suppressed via suppression row when mirror lags · excludes ambiguous and counts it · never includes unlinked
  • status is per app not per shop · counts contacts on shops with no status
  • preview rejects empty statuses · preview rejects out of scope app · saved audience names are unique case-insensitively · stale audience reads with stale flag
  • csv escapes formula cells · csv row count equals preview count · email routes sit behind requireAuth
  • migrations are 1..4 in order (existing test/migrate.test.ts, updated)
