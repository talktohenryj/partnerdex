Sprint 2 — Identify + custom attributes

Not started · repos: partnerdex + iziGift · branch email/s2-identify off email-upstream (see Q6) · migration 6

Why this ships now

An email is only as useful as what it knows about the store. Today an app can tell PartnerDex one thing: "this person logged in" (POST /api/contacts/ingest, one person per call, email required). It cannot say "this store's time zone is New York" or "cashback is on". S3's merge fields, S3's page buttons, and S5's weekly recap all need that. This sprint adds Mantle's identify call: one endpoint where an app describes a shop — its contacts and its custom attributes — in one payload. Henry defines the attribute keys in PartnerDex; values for keys he has not defined are ignored and reported back.

Why this is independently deployable

One migration that only creates tables, one new public route behind the existing ingest token, one settings page, one card on the customer page. POST /api/contacts/ingest is not changed and keeps working, so the deployed iziGift job keeps working until its own change ships. If S3 never ships, Henry still sees each store's settings and time zone on the customer page, and the Contacts store keeps filling from the new endpoint.

    CREATE TABLE IF NOT EXISTS custom_attributes (       -- the keys Henry defines, per app
  app_id           TEXT NOT NULL,
  key              TEXT NOT NULL,                     -- ^[a-z][a-z0-9_]{0,63}$
  label            TEXT NOT NULL,
  type             TEXT NOT NULL CHECK (type IN ('text','number','boolean','date')),
  description      TEXT NOT NULL DEFAULT '',
  show_on_customer INTEGER NOT NULL DEFAULT 1,
  created_at TEXT NOT NULL, updated_at TEXT NOT NULL,
  PRIMARY KEY (app_id, key)
) WITHOUT ROWID;
CREATE TABLE IF NOT EXISTS shop_attribute_values (   -- latest value per shop; a new value replaces the old
  app_id     TEXT NOT NULL,
  shop_id    TEXT NOT NULL,
  key        TEXT NOT NULL,
  value      TEXT NOT NULL,                           -- JSON scalar, already coerced to the key's type
  updated_at TEXT NOT NULL,
  PRIMARY KEY (app_id, shop_id, key)
) WITHOUT ROWID;
CREATE TABLE IF NOT EXISTS app_links (               -- how to deep-link into each app's admin pages
  app_id       TEXT PRIMARY KEY,
  admin_handle TEXT NOT NULL,                         -- e.g. easy-gift-cards
  pages        TEXT NOT NULL DEFAULT '[]',            -- JSON [{ key, label, path }]
  updated_at   TEXT NOT NULL
) WITHOUT ROWID;

    Coercion per type: text — string ≤ 500 chars (numbers and booleans stringified); number — finite number or numeric string; boolean — true/false or "true"/"false"; date — YYYY-MM-DD or full ISO, stored as ISO. null deletes the value. Anything else → wrong_type. One transaction per shop.

Identify — src/identify/identify.ts, src/server/identify.ts (new) identifyRouter(), mounted in src/server/index.ts next to the contacts ingest router, before requireAuth: app.use('/api/identify', express.json({ limit: '1mb' }), identifyRouter()), guarded by requireIngestToken (export it from src/server/contacts.ts; same CONTACTS_INGEST_TOKEN). Body is one shop or a batch: 
    { "shop": {                                   // or { "shops": [ … up to 500 … ] }
    "appId": "…", "shopId": "…", "myshopifyDomain": "example-candles.myshopify.com",
    "contact":  { "email": "…", "firstName": "…", "lastName": "…", "role": "owner", "source": "app_capture", "seenAt": "…" },
    "contacts": [ … same shape … ],          // either or both; both optional
    "customAttributes": { "timezone": "America/New_York", "cashback_enabled": true }
} }
    Per shop: resolve with resolveShopMatch() (src/contacts/upsert.ts); each contact → upsertContact() with that shop (same rules as today, including unlinked when the shop does not match); attributes → setShopAttributes() only when the shop matched (otherwise every key is ignored with reason shop_not_found). Response 200 { results: [{ shopId: string | null, matched: boolean, contacts: UpsertContactResult[], attributes: { saved, ignored } }] } in input order. 422 only for a malformed body (no shop/shops, more than 500 shops, a contact with no email). POST /api/contacts/ingest stays as it is.

Explicitly NOT in this sprint

  • Usage events (counts over time) — those stay on the Usage Metrics endpoint, because they add up instead of replacing a value. Usage Metrics S1 accepts the same shop block shape.
  • Attributes on a person (language, job title). The payload keeps room for contact.customAttributes later.
  • Audience rules on attributes ("cashback is off"). Possible later as another rule button.
  • Merge fields and page buttons in email — S3 reads what this sprint stores.
  • Removing /api/contacts/ingest (Q9).
