Sprint 6 — Scheduled emails

Not designed · after S5 and Usage Metrics S1–S4

S5 sends the weekly recap when iziGift calls. This sprint lets PartnerDex send a template on its own clock — "every Monday at 09:00 in each store's time zone" — and fill data from Usage Metrics instead of from the app. The weekly recap moves here; its template stays the same.

This sprint is not locked. It holds open questions, not a Build list. Write the Build list when the sprints before it ship.

Open questions

QuestionNotes so far
Where the data comes fromMap each data.* name to a usage metric and a window (for example redeemed_count = "Gift cards redeemed", 7 days). Lists such as campaigns_due do not fit a metric; keep the app call for those, or drop the section?
Comparison windowsUsage Metrics S3 has windows that end now (7d, 30d …). "The 4 weeks before this week" needs a window that ends 7 days ago. Add it to Usage Metrics, or compute it here?
Events the recap needsUsage Metrics S2 sends only order. The recap needs gift card redeemed, gift card sold, cashback issued, cashback redeemed (listed there as later).
Send conditionPer store: "send only when redeemed_count + sold_count > 0". A tiny rule list on the template, or a fixed "skip when every number is zero"?
CadenceWeekly in Q4, every two weeks otherwise: one schedule with a date rule, or two schedules?
Hand-over from S5While iziGift still calls /api/messages, both could send. The period dedupe key prevents a double send if both use the ISO week. Switch iziGift off in the same release?
