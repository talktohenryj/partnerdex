Sprint 4 — Usage on the customer page

Not started · repo: partnerdex · no migration

Planned change (Henry, 2026-11-04): when this sprint starts, it becomes the customer page redesign in Mantle's layout, not only a Usage card. Contacts, store details and audiences move to a side column; the main column holds the stat tiles, one panel per app, Usage with a window picker, Custom attributes (Email S2), usage and one-time charges, and a Timeline that includes email sends (Email S4). Email S2 keeps its simple Attributes card until then. Rewrite the Build list below before S4 starts — it still describes the Usage card only. Reference and mockup: Customer page redesign.

Why this ships now

This is the screen Henry liked in Mantle: open a merchant, see their orders and revenue next to what they pay. PartnerDex already shows MRR, plan, lifetime value and contacts on CustomerDetail; usage is the missing half of "is this merchant getting value".

Why this is independently deployable

Read-only over S1 and S3 tables, through a separate request. If the app has no metric with show_on_customer = 1, or the request fails, the card does not render and the page is exactly today's page. getCustomer() and /api/customers/:shopId are not changed.

Build

  1. Read model — src/usage/compute.ts computeCustomerUsage(shopId, { appIds, window, compare = true }): CustomerUsage. For each metric where show_on_customer = 1 and app_id in scope (same scope() rule as src/customers/index.ts), call aggregateMetric() from S3 for the window and, when compare, for the window before it. Also return lastEventAt and eventCount for the shop. 
    interface CustomerUsage {
  window: '24h'|'7d'|'30d'|'90d'|'365d'|'mtd'|'all';
  from: string; to: string;
  lastEventAt: string | null;
  metrics: Array<{ id; appId; appName; name; format: 'number'|'usd';
                   value: number; previous: number | null }>;
}
  2. Route — src/server/index.ts GET /api/customers/:shopId/usage?window=30d&appId= next to /api/customers/:shopId (line 275). Separate request so a slow usage query never delays the customer header.
  3. Card — web/src/components/CustomerUsage.tsx (new) Rendered on the Overview tab of CustomerDetail.tsx, below the header tiles and above AppsTable (line 631). Title "Usage", window pills (7d / 30d / 90d / 365d / MTD / All; default 30d; kept in the URL as ?usage=90d), tile grid (reuse the MetricCard styling, not the chart), value formatted with web/src/format.ts currency helper when format = 'usd', delta vs previous window, "Last event 20 hours ago" under the title, link "Edit metrics" → Usage metrics page. Empty state when the shop has zero events: "No usage events from this store yet."
  4. Usage events link — "View events" on the card opens Usage events (S1) pre-filtered to this shopId.
  5. API helper — fetchCustomerUsage(shopId, window, appId) in web/src/api.ts, types beside CustomerDetail.
