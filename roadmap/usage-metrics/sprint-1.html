Sprint 1 — Ingest + raw usage events

Not started · repo: partnerdex · migration 4

Why this ships now

PartnerDex has no place to put app-side events. Every day without the table is a day of usage history that is gone for good — the Partner API cannot replay it. This sprint opens the door and keeps everything that comes through it.

Why this is independently deployable

One new migration that only creates tables, one new router, one new page. No existing query reads usage_events. With USAGE_INGEST_TOKEN unset the endpoint answers 503 and nothing else changes. Foundation-only on the read side, but it is split out so S2 can start writing (and history can start piling up) while S3 is still being built.

Explicitly NOT in this sprint

  • Metric definitions, sums, windows (S3/S4).
  • Any iziGift change (S2).
  • Deleting events. A producer zeroes an event by re-sending it, the same way iziGift does with Mantle.
